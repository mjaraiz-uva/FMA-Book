1. Architecture Overview

The DEPLOYERS pandemic shock system simulates the economic impact of the COVID-19 pandemic by encoding real-world lockdowns, reopenings, and policy interventions as time-varying perturbations applied to an already-calibrated agent-based economy. The system operates through three simultaneous shock channels plus one protective policy mechanism:

  1. Sector-specific supply shocks — workers in affected sectors are confined (cannot work), reducing production capacity through the natural labor constraint.
  2. Export and import shocks — multiplicative factors reduce external sector flows, capturing global trade disruption.
  3. Kurzarbeit (short-time work) subsidies — government wage payments to confined workers prevent demand collapse.
  4. Pandemic firm protection — pre-pandemic firms are shielded from bankruptcy to simulate real-world government support.

The PANDEMIC_TIMELINE Block

The shock specification uses a PANDEMIC_TIMELINE block in the input .dep file. Each month of the crisis is defined independently with:

  • Sector-specific capacity factors: pairs of <sectorIndex> <factor> where factor ranges from 0.0 (complete shutdown) to 1.0 (normal operation)
  • ExportShock: multiplicative factor on export demand (0.0–1.0)
  • ImportShock: multiplicative factor on import supply (0.0–1.0)
  • KurzarbeitParticipation: fraction of eligible firms participating in short-time work (0.0–1.0)

Activation Logic

The pandemic activates at free-market month PandemicShockFromFM (typically 3, allowing a few normal FM months for baseline comparison). The key functions in source/DEPLOYERS.cpp:

  • getPandemicTimelineMonth() — returns the current timeline month index (0-based from PandemicShockFromFM), or −1 if not active
  • isPandemicMonth() — returns true if the current month is within the pandemic window
  • getPandemicStartAbsMonth() — returns the absolute month when the pandemic starts (FinishCalibrationAt + PandemicShockFromFM)

The duration is determined by the length of the _PandemicTimeline vector (parsed from the PANDEMIC_TIMELINE block in the input file).

2. Implementation Details

2.1 Supply Shocks via Worker Confinement

Source: source/Individual.cpp, lines 290–303

The supply shock is implemented through worker confinement, not through a direct production multiplier. This is a critical design decision documented in the code:

"This is the ONLY pandemic supply shock — it flows through the natural labor constraint (availableWorkTime → MaxFromWorkTime → producedUnits). No separate production multiplier needed."

At the start of each month (CWorker::monthInitialize()):

  1. Each worker's myAvailableTime is reset to 1.0 (normal)
  2. If it is a pandemic month and the worker is employed:
    • The worker's employer's sector is looked up
    • The sector's capacity factor is retrieved from the timeline via CData::getPandemicSectorShock(sector)
    • If the factor is less than 1.0, a random draw determines whether this specific worker is confined: if getRandom01() > sectorFactor, the worker is confined (myAvailableTime = 0)
  3. Confined workers cannot produce output, which naturally reduces the firm's MaxFromWorkTime constraint in Producer::DetermineProducibleUnits()

This approach is elegant because it reuses the existing labor constraint mechanism. A sector with factor 0.05 (accommodation during first lockdown) means only 5% of its workers can work — the other 95% have myAvailableTime = 0.

2.2 Export and Import Shocks

Source: source/ExtSectors.cpp, lines 213–259

Exports (demand side): During pandemic months, the buy quantity for each external sector's demand is multiplied by the timeline's exportShock factor. This reduces how much foreign countries want to buy from the domestic economy.

Imports (supply side): The sell quantity for each good type from external sectors is multiplied by the timeline's importShock factor. This reduces the availability of imported goods.

Both shocks support time-varying values from the timeline. If no timeline exists, they fall back to static parameters PandemicExportShock and PandemicImportShock.

2.3 Kurzarbeit (Short-Time Work Subsidies)

Source: source/Government.cpp, lines 357–412; source/Producer.cpp, lines 2009–2023

The Kurzarbeit system has two components:

Government payments (GovKurzarbeitPayments())

  • Targets employed workers who are confined (myAvailableTime == 0) at pre-pandemic firms
  • The government pays KurzarbeitWageFraction (90% in the Austria specification) of the worker's normal salary
  • Participation is stochastic: each eligible firm participates with probability equal to KurzarbeitParticipation from the timeline
  • Payments are recorded in the SAM accounting framework
  • Only workers at firms created before the pandemic start are eligible — post-pandemic newborns must survive on market conditions alone

Producer layoff prevention (Producer.cpp)

  • When isPandemicMonth() is true and KurzarbeitWageFraction > 0, pre-pandemic firms with Kurzarbeit participation do not lay off confined workers
  • This prevents the death spiral: confinement → layoff → zero income → demand collapse

2.4 Pandemic Firm Protection

Source: source/World.cpp, lines 2686–2694

During pandemic months, the DismantleAndStartNewProducers() function applies selective protection:

// During pandemic: government support keeps PRE-PANDEMIC firms alive (no bankruptcies).
// Firms born during the pandemic are not eligible -- they never had pre-pandemic activity
// to preserve, and shielding them creates an artificial zero-death-rate accumulation.
if (isPandemicMonth()) {
    long pandemicStart = getPandemicStartAbsMonth();
    if (pandemicStart >= 0 && pProducer->getinitialMonth() < pandemicStart)
        continue;  // pre-pandemic firm: protected
    // post-pandemic newborn: subject to normal bankruptcy rules
}

This distinction is critical: protecting ALL firms (including post-pandemic newborns) would create artificial firm population inflation, since firms born during the crisis face abnormal conditions and many should naturally fail. Only firms that existed before the pandemic — representing the economy's pre-crisis productive capacity — receive protection.

3. Calibration & Diagnostics — The Crucial Role of Snapshot Curves

This is the most important section of this report. The DEPLOYERS simulator stores complete time series of all GUI plot curves inside every snapshot file. These curves are the primary tool for understanding, calibrating, and debugging simulations — both baseline and pandemic. Never rely on log files alone.

3.1 Extracting Curves from Snapshot PlotsData

Every snapshot file (OUTPUT/SimName_CC_NNN.dep) contains a PlotsData section with the following structure:

PlotsData { <nWindows>
 <windowTitle> { <nCurves>
  <curveIdx> { <nValues> <v0> <v1> <v2> ... }
  ...
 }
 ...
}

The canonical PowerShell extraction function (proven working, used across all analysis scripts):

function Extract-CurveValues {
    param([string]$SnapshotPath, [string]$WindowName, [int]$CurveIndex)
    $content = Get-Content $SnapshotPath -Raw
    $plotsIdx = $content.IndexOf("PlotsData")
    if ($plotsIdx -lt 0) { return $null }
    $windowStart = $content.IndexOf("$WindowName { ", $plotsIdx)
    if ($windowStart -lt 0) { return $null }
    $sub = $content.Substring($windowStart,
               [Math]::Min(500000, $content.Length - $windowStart))
    $marker = " $CurveIndex { "
    $idx = $sub.IndexOf($marker)
    if ($idx -lt 0) { return $null }
    $afterMarker = $sub.Substring($idx + $marker.Length)
    $parts = $afterMarker -split '\s+' | Where-Object { $_ -ne '' }
    $nValues = [int]$parts[0]
    $values = @()
    for ($i = 1; $i -le $nValues -and $i -lt $parts.Count; $i++) {
        if ($parts[$i] -eq '}') { break }
        $values += [double]$parts[$i]
    }
    return $values
}
Rules for using this function:
  • NEVER write inline PowerShell for curve extraction — always use a .ps1 script file
  • NEVER use powershell -Command "..." for anything beyond one-liners — use powershell -File script.ps1
  • The function reads the ENTIRE snapshot file into memory (snapshots can be 10–50 MB), so it needs the 500,000 character substring limit

The FirmsPerFirmsize 0–9 Curve: The Single Most Important Diagnostic

The micro-firm share (firms with 0–9 employees as a percentage of all firms) is the earliest and most reliable indicator of simulation health. In a well-calibrated economy:

  • The micro-firm share should settle at approximately 88–91% during free-market simulation
  • This matches real-world data (Austria empirical: 87.4%, Eurostat)
  • The value is not an input but an emergent outcome of the I-O factor income structure and Darwinian selection
Warning signs:
  • If the share drifts above 95%: the economy is fragmenting — firms are not growing
  • If the share reaches 99–100%: calibration has failed — there are no medium/large firms
  • If the share drops below 85%: excessive consolidation, possibly due to aggressive parameters

OLS Growth Method for realGDP

The standard method to extract GDP growth from a baseline (non-pandemic) simulation:

  1. Find FinishCalibrationAt in the *_Log.dep file (line: FinishCalibrationAt NOW SET TO: NNN)
  2. Extract curve 7 from the GovValues window in the last snapshot's PlotsData
  3. Take 12 free-market months: values at indices [calibEnd+1 .. calibEnd+12]
  4. Run OLS linear fit: GDP(t) = a + b*t, t = 0..11
  5. Annual growth = 12 * b / a * 100%
Note: For pandemic simulations, the OLS method is NOT appropriate because the U-shaped trajectory makes linear fit misleading. Instead, use point-to-point growth: compare FM month N to FM month N+11.

3.3 Detecting Calibration Problems Early

The simulation progresses through four stages before entering free-market dynamics:

  1. PreCalibration (months 0–24): Sequential producer startup, initial ramp-up
  2. AssistedCalibration: Subsidized production to reach SAM targets
  3. TransitionCalibration: Subsidies phase out gradually
  4. RealMarketSimulation: Free market (no subsidies)

Early detection using snapshot curves:

  • Month 24–36: Check if TotalProduction is approaching the SAM target. If it is flat or declining, the simulation is struggling.
  • Month 36–48: The FirmsPerFirmsize 0–9 curve should be settling. If it is still rising toward 100%, the Darwinian mechanism is failing to produce viable medium/large firms.
  • At FinishCalibrationAt: Check that the micro-firm share is in the 88–91% range. Also verify that Employment curve 1 (unemployment) is at a reasonable level.

Interpretation

Y1 contraction (−4.62% vs. empirical −6.6%): The model captures approximately 70% of the actual pandemic GDP loss, with a standard error of the mean of just 0.18 pp (SEM = SD / sqrt(12) = 0.64 / 3.46). The 2.0 pp gap may reflect consumer confidence effects, precautionary savings, and voluntary demand reductions beyond mandated restrictions — factors not encoded in the supply-side shock specification.

Y2 recovery overshoot (+13.48% vs. empirical +4.6%): The V-shaped bounce reflects the Darwinian mechanism aggressively filling demand gaps once restrictions lift. In reality, Austria's recovery was constrained by persistent supply chain disruptions, labour market frictions, and lingering uncertainty that the model's simplified labour market does not fully capture.

Y3 normalization (+2.60% vs. empirical +4.7%): By year 3, the economy is approaching its structural growth trajectory. The model undershoots slightly, possibly because the recovery overshoot in Y2 "borrowed" growth from Y3.

Firm dynamics: Both birth and death rates roughly double during the crisis (births from ~16,500 to ~31,400/year; deaths from ~13,500 to ~28,000/year), reflecting heightened creative destruction. The selective Kurzarbeit protection prevents artificial firm population inflation. Firm size distributions remain stable through the crisis (87–93% micro-firms), indicating that the pandemic shock does not distort the I-O-implied industrial structure.

Diagnostic Patterns That Predict Failure

  1. Micro-firm share > 95% by month 48: The Darwinian mechanism cannot create viable medium/large firms. The I-O structure may have extreme sectoral imbalances.
  2. Price crash (price ≤ 0): Usually occurs in countries with very large trade imbalances or unusual accounting conventions in the I-O table. The external sector flows overwhelm domestic production capacity.
  3. Calibration timeout (> 45 minutes): The economy cannot achieve production/wealth stability. Often correlated with high micro-firm shares.
  4. TotalProduction stuck below SAM target: The I-O table implies a production structure that the Darwinian mechanism cannot realize at w32 scale.

6. Lessons for AI-Assisted Simulation Debugging

Principle 1: Snapshot Curves Are the Primary Debugging Tool

Never rely on log files alone. The log file tells you what happened (milestones, errors). The snapshot curves tell you why it happened and whether the underlying dynamics are healthy. A simulation can appear to complete successfully (no errors in log) while producing economically meaningless results — only the curves reveal this.

Principle 2: The FirmsPerFirmsize 0–9 Curve Is the Earliest Indicator

Pattern: If the micro-firm share (FirmsPerFirmsize curve 0) does not drop to approximately 90% by month 48, the simulation will likely fail to produce meaningful GDP estimates. A 100% micro-firm share means no firm has more than 9 employees, the Darwinian selection mechanism is not working, and GDP estimates from such a simulation are unreliable.

Principle 3: Always Use the Canonical Extraction Function

The Extract-CurveValues function is the proven, canonical way to read snapshot curves. Never write inline PowerShell for curve extraction, parse snapshot files with grep/awk/sed, or attempt to read PlotsData manually.

Principle 4: Understand the Shock Propagation Chain

For pandemic debugging, trace the chain:

  1. Worker confinement (Individual.cpp) — check that myAvailableTime = 0 is being set correctly
  2. Production reduction (Producer.cpp) — verify that MaxFromWorkTime is reduced
  3. Export/import reduction (ExtSectors.cpp) — confirm external flows are multiplied by shock factors
  4. Kurzarbeit payments (Government.cpp) — verify confined workers at pre-pandemic firms receive wage subsidies
  5. Firm protection (World.cpp) — confirm pre-pandemic firms are not being dismantled

If GDP is not dropping enough during the pandemic, check steps 1–3. If GDP is dropping too much, check steps 4–5.

Principle 5: Pre-Pandemic vs. Post-Pandemic Firm Distinction

All three protective mechanisms (Kurzarbeit, layoff prevention, bankruptcy protection) apply ONLY to firms created BEFORE the pandemic start. Firms born during the pandemic face normal market selection. This prevents artificial firm population inflation, zero-death-rate accumulation, and distorted firm size distributions post-pandemic.

Principle 6: Point-to-Point vs. OLS for Pandemic GDP

For baseline (non-pandemic) simulations, OLS linear fit over 12 FM months is the standard method. For pandemic simulations, the U-shaped trajectory makes OLS misleading. Use point-to-point comparison (FM month N to FM month N+11) instead.

Principle 7: The Dual Capability of the I-O Table

The same I-O inter-sectoral linkages that drive baseline GDP accuracy also serve as the transmission mechanism for pandemic shocks. When a sector shuts down:

  • Backward linkages: demand for that sector's inputs collapses
  • Forward linkages: supply to that sector's customers is disrupted
  • Final demand effects: laid-off workers reduce household consumption across all sectors
  • Fiscal effects: government tax revenue falls, transfer payments rise

None of these transmission channels are explicitly programmed. They emerge automatically from the I-O production structure and the agent-based dynamics.
